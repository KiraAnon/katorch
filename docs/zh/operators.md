# 算子支持（中文）

全部在 MT6897 / MDLA 5.0 / Neuron 7.x、fp16 下实测：把每个算子单独建图，跑
build → compile → run，再和 torch fp32 参考对拍（判据：相对误差 < 1 %）。

"能用"的定义是：build 成功、compile 返回 rc=0、run 返回 rc=0、数值对得上。
其余都在下面单列。

> **请按字面读状态列。** 标"实测"的有留存的测量；标"已定义未测"的实现了 shape 规则、
> 在大图里编过，但从没被单独拿出来量过数值。

英文版：[../operators.md](../operators.md)

## 三、被记为不可用的算子

| 算子 | 状态 | 原因 | 替代 |
|---|---|---|---|
| **DIV**（30） | ⚠️ **记录冲突** | 11-14 的扫描：build 过、compile 返回 `-516`。11-15 的移植笔记又把它列为可用，但没有留下那次的日志。 | 复测之前按不可用处理：乘 CPU 预先算好的倒数 |
| **LOG**（60） | ⚠️ **记录冲突** | 同上 | 留 CPU，或分段线性 |
| **SIN**（85） | ⚠️ **记录冲突** | 同上 | 留 CPU；泰勒展开在 fp16 下精度不够 |
| **SLICE** | 不支持 | 没有这个算子 | RESHAPE + CONCAT |
| **GATHER** | 不支持 | 没有这个算子 | 留 CPU |
| **FLOOR** | 不支持 | — | 用 CAST 截断 |
| **LOG_SOFTMAX** | 不支持 | — | 手写展开 |

DIV/LOG/SIN 这个冲突是**文档缺陷，不是硬件之谜**。要定案就自己跑一遍：
`测试/optable.py` 会把表里每一行都建图并打印 `OK` / `BAD` / `COMPILE` / `RUN`。
如果你的结果是三个都 OK，改这张表并把日志一起提交。

**在此之前，把这三个当不可用。** `lowering.py` 是乐意生成它们的（`div`/`log`/`sin`
都有 lowering 分支）；真要失败，失败发生在 `compile`。

## 四、归约是 3 个输入（最容易错的一处）

`MEAN`、`REDUCE_SUM`、`REDUCE_MAX` **不是**两输入算子。只给两个会直接
`-516 UNMAPPABLE`，而且不提示少了哪个参数。

```
OP 31 3 <input> <axis_const> <act_code> 1 <output>
```

* `axis_const` —— **type 4**（TENSOR_INT32），`a -1` 表示最后一维，或写具体轴号
* `act_code` —— **type 4**，`a 0`

完整例子，`[512,256]` 求每行均值 → `[512,1]`：

```
OPD 0 8 2 512 256 0 0 i
OPD 1 4 1 1 0 0 a -1
OPD 2 4 1 1 0 0 a 0
OPD 3 8 2 512 1 0 0 o
OP 31 3 0 1 2 1 3
IO 1 0 1 3
END
```

## 五、硬规则

### 5.1 参数类型

```c
// CONV_2D 的 pad / stride 必须是 nd=0 的 INT32 标量
self._opd(oid, 1, (), "a %d" % k)     // type=1, nd=0
```

FC 的 `activation_code` 是反过来的：**必须 type 4**。写 type 1 不报错——它会把这个算子的
第一个输入直接透传，于是图能跑、数是错的、还返回 rc=0。

### 5.2 广播

| 模式 | 支持 | 说明 |
|---|---|---|
| `[S,D] + [S,D]` | ✅ | 同形 |
| `[S,D] + [1,D]` | ✅ | 单侧 |
| `[S,D] + [S,1]` | ✅ | 单侧 |
| `[S,1] * [1,D]` | ❌ | 不支持双向广播 |

被广播的那一侧必须是图输入或常量，不能是算出来的值。

### 5.3 常量类型

| type | 含义 | 字节 |
|---|---|---|
| 0 | FLOAT32 标量 | 4 |
| 1 | INT32 标量 | 4 |
| 3 | TENSOR_FLOAT32 | 4 |
| 4 | TENSOR_INT32 | 4 |
| 8 | TENSOR_FLOAT16 | 2 |

**0 维 fp16 标量**（nd=0 + type=8）编不过。用 Python float 生成 nd=1 的常量。

### 5.4 序列长度

`S` 必须是 2 的幂。`16 / 64 / 256` 能编，`36 / 100 / 144` 返回 `-516 UNMAPPABLE`。
这不是尺寸上限，是布局规则。

### 5.5 fp16 累加溢出

```
2048 维上 sum(x²)  >  65504  →  inf  →  rsqrt(inf) = 0  →  整层全零
```

没有报错、没有警告。要么预缩放 K 使 `K > sqrt(var * D / 65504)`，要么用
`KAcustom/` 里的 `BalancedNorm` 构造。

### 5.6 CONV_2D 布局

| 项 | 格式 |
|---|---|
| 输入 | NHWC `[N,H,W,C]` |
| 权重 | OHWC `[O,H,W,C]`——torch 的 OIHW 要 permute |
| 输出 | NHWC |
| 权重 | 必须是常量 operand，不能是算出来的值 |

## 六、吞吐

| 算子 | 规模 | 吞吐 |
|---|---|---|
| CONV_2D 96→96 k3 @1024² | 173.9 GFLOP | **701.8 GFLOP/s** |
| CONV_2D 384→384 k3 @256² | 173.9 GFLOP | **1189.8 GFLOP/s** |
| FC 2048→2048 @S=256 | — | ~117 GFLOP/s |
| BATCH_MATMUL | 0.27 GFLOP | 3.0 ms → 89 GFLOP/s |

**CONV 是 MDLA 的专用通路**，比把同样的活写成 FC 快 6–10 倍。
模型里有卷积的话，那就是硬件真正划算的地方。
